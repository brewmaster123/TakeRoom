# TakeRoom

Личная студия для iPhone с iOS 17 и новее. Один проект хранит текст, бит и несколько видеодублей. У каждого дубля свой микшер с битом, основным голосом и двумя бэками. Звуковые файлы, записи и текст остаются на телефоне.

## Сборка для GBox

1. Распакуй содержимое этого архива в корень своего GitHub-репозитория. Рядом должны лежать папки TakeRoom.xcodeproj, App, Audio, Tests и .github/workflows.
2. Запушь изменения. Сборка **Build unsigned IPA** запустится через GitHub Actions. Её также можно запустить вручную через **Actions → Build unsigned IPA → Run workflow**.
3. В завершённой сборке скачай артефакт **TakeRoom-unsigned-IPA**. Распакуй архив артефакта и возьми файл **TakeRoom-unsigned.ipa**.
4. Подпиши IPA и установи на iPhone своим обычным способом через GBox.

Проект использует системные библиотеки Apple и zlib. Файл проекта Xcode и общая схема уже включены. Идентификатор приложения по умолчанию — `studio.takeroom.prototype`. Сборке GitHub не нужны ключи подписи.

## Запись первого куплета

- Создай проект. На вкладке **Текст** выбери аудиофайл из «Файлов», например MP3, WAV или M4A. На волне прослушай бит и отметь начало и конец фрагмента любой длины в пределах трека. В настройках звука можно пройти тест «та» и сохранить поправку для новых записей. В микшере кнопка «Совместить с битом» открывает просмотр дубля со сдвигом и повтором фразы. Можно включить повтор и писать куплет под бит.
- Через кнопку наушников открой **Звук**. Для проводного микрофона и Bluetooth-наушников оставь переключатель микрофона Bluetooth выключенным. Выбери микрофон и открой системное меню вывода рядом с названием наушников. После выбора проверь фактические вход и выход. Предпочтение входа сохраняется. Доступные сочетания устройств определяет iOS.
- На вкладке **Запись** настрой шрифт, отступ и скорость суфлёра. Скорость 0 оставляет текст неподвижным. Нажми **Снять новый дубль**. Проверь устройства, нажми **Начать запись** и прочитай текст после отсчёта. Запись завершается по кнопке или в конце фрагмента. Суфлёр виден только исполнителю.
- Выбери дубль и по очереди запиши **Бэк 1** и **Бэк 2**. В наушниках звучит текущий микс с уже записанными партиями. Перезаписываемая партия на время записи отключается. Можно закончить бэк раньше конца ролика. Новый бэк заменяет предыдущий после завершения записи.
- На вкладке **Микс** выставь громкость каждой дорожки. Голос основного дубля связан с изображением. Бит и оба бэка можно сдвинуть на ±1000 мс с шагом 5 мс. Положительный сдвиг ставит дорожку позже. Для голоса и бэков есть реверберация. Для картинки доступны оригинал, чёрно-белый и тёплый фильтры.
- Нажми **Посмотреть и послушать** для просмотра текущих настроек. Готовый MP4 можно сохранить в «Фото» или отправить через системное меню.

## Экспорт Stems

Вкладка **Микс → Stems · экспорт ZIP** открывает системное меню, где архив можно отправить или сохранить в «Файлы».

| Файл | Содержимое |
|---|---|
| 00-video.mp4 | Видео выбранного дубля с выбранным фильтром, без аудиодорожки |
| 01-beat.wav | Бит |
| 02-lead.wav | Основной голос |
| 03-back-1.wav | Первый бэк |
| 04-back-2.wav | Второй бэк |

Все WAV начинаются с нулевой отметки проекта, имеют одинаковую длину и формат PCM 44,1 кГц, 16 бит, стерео. Сдвиги уже учтены. Stems содержат сухие дорожки до фейдеров, mute и реверберации. Пустой бэк даёт тишину. В редакторе поставь все пять файлов на нулевую отметку.

## Быстрый тест на телефоне

С подключённым микрофоном и наушниками запиши короткое «раз» на удар бита, затем «два» и «три» на разные бэки. В микшере проверь каждый голос отдельно. Сохрани короткий MP4 и ZIP, импортируй WAV с видео в редактор и проверь синхронизацию. Если голос совпадает с губами, для компенсации задержки наушников сдвигай бит. У каждой Bluetooth-связки может быть свой сдвиг.

## Проверки проекта

`python3 Tests/test_audio.py` проверяет используемый приложением код C. Проверки покрывают временные сдвиги в обе стороны, независимые уровни и отключение дорожек, реверберацию, пустой бэк, целостность ZIP и отсутствие частичного архива при ошибке.

На macOS `bash Tests/render-smoke.sh` запускает настоящий экспорт AVFoundation на коротком синтетическом ролике с импульсом. Проверяются позиции сигналов в WAV, тишина пустого бэка, звуковая дорожка обычного MP4 и её отсутствие в видео для Stems. Обе проверки включены в GitHub Actions.
